# Documents in Other Languages

DocGuard reads documentation written in any language. The structural labels it
looks for are matched by **id**, not by English text, so a project that writes
its documents in Portuguese, Spanish or any other language does not need
English headings. This page is the reference: the closed list of ids, the
marker, the built-in sets, how to extend them, what is skipped and why, and what
is still open.

## What is a label, and what is not

A label is a structural word DocGuard has to find to judge a document:

- the required headings of the canonical documents (`ARCHITECTURE.md`,
  `DATA-MODEL.md`, `SECURITY.md`, `TEST-SPEC.md`, `ENVIRONMENT.md`) and the
  Test-Spec source-to-test map,
- the README's Installation, Usage and License sections,
- the changelog's unreleased section,
- the Spec Kit section names (`spec.md`, `plan.md`, the bugfix shape) and the
  `Phase` word in `tasks.md`,
- the decision-record status and supersession words, and the lifecycle `Status`
  label.

Everything else stays language-neutral and is not a label: prose, requirement
ids (`FR-001`, `SC-001`, `REQ-001`), task ids (`T001`), the `Spec ID`, the
`docguard:spec-type` marker and every other `docguard:` marker. Spec Kit's own
templates stay English and `specify` is untouched; DocGuard never rewrites a
Spec Kit template.

## The heading marker

```markdown
## Visão geral do sistema
<!-- docguard:heading system-overview -->

Texto.
```

- The marker is the next non-blank line under the heading, outside a code fence
  and outside any larger comment. Anywhere else it is ignored and reported as
  STR009 (misplaced).
- It names an id; the heading text can be anything in any language, and the
  heading keeps the text, and the anchor, the author wrote.
- A marker is explicit, so it works in every language and in a project with no
  `docs.language`. It is the only new behavior without `docs.language`.
- When the marker and the heading's text disagree (the heading is the English
  label of another id), the marker wins and STR009 says so.
- An HTML comment is invisible in GitHub, GitLab and every CommonMark renderer.

## Built-in sets: `pt` and `es`

Set `docs.language` in `.docguard.json` to a [BCP 47](https://www.rfc-editor.org/info/bcp47)
tag:

```json
{ "docs": { "language": "pt-BR" } }
```

A tag is matched by its primary subtag: `pt-BR` and `pt-PT` use the `pt` set,
`es-MX` uses `es`. The sets are the table above. Matching folds case and accents
(`Visao geral` matches `Visão geral`), compares whole headings, and drops a
leading section number (`5.4 Camadas` matches `Camadas`). English is always
accepted, in every language, so mixed documents work. With `docs.language` absent
or `"en"` the matching is the English matching it has always been, byte for byte.
An invalid tag is reported and treated as absent.

The headings and words of the `pt` and `es` sets were reviewed by a native
speaker on 2026-11-17; only the prose word lists below (task T033) still wait
for that review. A heading that is
missing from a set is never a dead end: the marker always works.

## Your own wording: `docs.labelAliases`

```json
{
  "docs": {
    "language": "pt-BR",
    "labelAliases": {
      "requirements": ["Requisitos do sistema"],
      "accepted": ["Vigente"]
    }
  }
}
```

Keys are ids from the table; each value is a list of strings. Project aliases
extend the built-in sets and never replace them. A front-matter `status:` in a
decision record goes through the same aliases. Aliases are read only when
`docs.language` is set.

## A language with no built-in set

Any other valid tag (`"de"`, `"fr"`, `"ja"`) is accepted and has no built-in set.
DocGuard cannot tell a missing section from one written in that language, so a
required heading that has no English form, no marker and no `docs.labelAliases`
entry does not produce a missing-section finding (STR003 and its siblings). The
document is listed under "DocGuard could not read" in `guard`, and in
`strict.couldNotRead` in `guard --format json`, with the cause
`language-not-supported`, the language and the fix. That entry never changes the
exit code. Add a marker or an alias and the entry disappears.

## Documents named by language

With `docs.language` set, a document's own name can say it is in another
language: `README.pt-BR.md`, `docs-canonical/ARCHITECTURE.pt-BR.md`, or a file
under `i18n/pt-BR/` or `locales/pt-BR/`. Its labels resolve with that language's
set and its text metrics are skipped as for any language but English. The
language is never inferred from the text, and without `docs.language` nothing is
inferred.

## What is skipped, and why

A check that cannot judge a document because of its language says so instead of
passing silently or inventing a number.

| Check | In a language other than English |
|---|---|
| Passive voice (DQ001), Flesch Reading Ease and Flesch-Kincaid (DQ004, DQ005) | Skipped: the rules are English grammar. Reported with the reason `language-not-supported`; no number, no finding, not counted in the score. |
| Negation (DQ007), conditional (DQ008), compound requirement (DQ003), ambiguous pronouns | Skipped until a native speaker has reviewed the `pt` and `es` word lists (see below). |
| Sentence length (DQ006) | Runs where the script separates words with spaces; skipped for `zh`, `ja`, `th`, `lo`, `km`, `my`. |
| Docs-Diff's tech stack, Metrics-Consistency, semantic claims | Report `language-not-supported` for the documents they would have read. |
| Agent-instruction files (`AGENTS.md`, `CLAUDE.md`, ...) and the instruction audit | Out of scope: they get no alias and no `language-not-supported` entry. |

The tokenizer and the sentence splitter are Unicode-aware for a non-English
`docs.language` (`não` is one word) and unchanged for English.

## What the writers do

- `docguard init` and `docguard generate` write the marker under each required
  heading of the documents they create, in English too. With `docs.language` set
  to `pt` or `es` the heading text is the first alias of the set; for any other
  language the heading is English and the marker carries the id. A new
  `CHANGELOG.md` gets `## [Não lançado]` or `## [Sin publicar]` plus its marker,
  and `## [Unreleased]` otherwise.
- `docguard generate --plan --write` and `sync` put a generated block under the
  heading that already holds the section, in any accepted form. When no heading
  exists they write the first alias plus the marker, never an English heading
  into a translated document, and for a language with no set they write the
  block without a heading and report it.
- `docguard fix --write` inserts the changelog section as `## [<first alias>]`
  plus the marker.
- No existing document is rewritten by `init` or `generate`.

## Open

The closed-class word lists behind the negation, conditional,
compound-requirement and pronoun metrics are not enabled for any language but
English until a native speaker of `pt` and `es` has reviewed them (task T033 of
spec 104). Until that review is recorded those four metrics are skipped, not
guessed. The heading and word sets above are data: a correction is an issue or a
pull request, and the marker and `docs.labelAliases` work meanwhile.

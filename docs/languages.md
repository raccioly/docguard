# Documents in Other Languages

DocGuard reads documentation written in any language. It matches the structural
labels by **id**, not by English text. A project that writes its documents in
Portuguese, Spanish or any other language does not need English headings. This
page is the reference. It covers the closed list of ids, the marker and the
built-in sets. It also covers how to extend them, what DocGuard skips and why,
and what is still open.

## What is a label, and what is not

A label is a structural word that DocGuard must find to judge a document:

- the required headings of the canonical documents (`ARCHITECTURE.md`,
  `DATA-MODEL.md`, `SECURITY.md`, `TEST-SPEC.md`, `ENVIRONMENT.md`) and the
  Test-Spec source-to-test map,
- the README's Installation, Usage and License sections,
- the changelog's unreleased section,
- the Spec Kit section names (`spec.md`, `plan.md`, the bugfix shape) and the
  `Phase` word in `tasks.md`,
- the decision-record status and supersession words, and the lifecycle `Status`
  label.

Everything else is language-neutral and is not a label. This includes prose,
requirement ids (`FR-001`, `SC-001`, `REQ-001`), task ids (`T001`), the `Spec ID`,
the `docguard:spec-type` marker and every other `docguard:` marker. Spec Kit's own
templates stay in English, and `specify` is untouched. DocGuard never rewrites a
Spec Kit template.

reports an unknown id in `docs.labelAliases` and ignores it. The table is
generated from `cli/shared-labels.mjs`. `docguard explain STR009` prints the

## The heading marker

```markdown
## Visão geral do sistema
<!-- docguard:heading system-overview -->

Texto.
```

- The marker is the next non-blank line under the heading. It must be outside a
  code fence and outside any larger comment. Anywhere else, DocGuard ignores it
  and reports STR009 (misplaced).
- It names an id. The heading text can be anything, in any language. The heading
  keeps the text and the anchor that the author wrote.
- A marker is explicit, so it works in every language and in a project with no
  `docs.language`. It is the only new behavior without `docs.language`.
- If the marker and the heading text disagree (the heading is the English label
  of another id), the marker wins and STR009 says so.
- An HTML comment is invisible in GitHub, GitLab and every CommonMark renderer.

## Built-in sets: `pt` and `es`

Set `docs.language` in `.docguard.json` to a [BCP 47](https://www.rfc-editor.org/info/bcp47)
tag:

```json
{ "docs": { "language": "pt-BR" } }
```

DocGuard matches a tag by its primary subtag. `pt-BR` and `pt-PT` use the `pt`
set. `es-MX` uses `es`. The sets are the table above. Matching ignores case and
accents (`Visao geral` matches `Visão geral`). It compares whole headings and
drops a leading section number (`5.4 Camadas` matches `Camadas`). DocGuard always
accepts English, in every language, so mixed documents work. If `docs.language`
is absent or `"en"`, the matching is the same English matching as always, byte
for byte. DocGuard reports an invalid tag and treats it as absent.

A native speaker reviewed the headings and words of the `pt` and `es` sets on
2026-11-17. The same person reviewed the prose word lists behind the text metrics
(task T033, see below). If a heading is missing from a set, you are not stuck.
The marker always works.

## Your own wording: `docs.labelAliases`

```json
{
  "docs": {
    "language": "pt-BR",
    "labelAliases": {
      "requirements": ["Requisitos do sistema"],
      "accepted": ["Vigente"]
    }
  }
}
```

Keys are ids from the table. Each value is a list of strings. Project aliases
extend the built-in sets. They never replace them. A front-matter `status:` in a
decision record uses the same aliases. DocGuard reads aliases only when
`docs.language` is set.

## A language with no built-in set

DocGuard accepts any other valid tag (`"de"`, `"fr"`, `"ja"`), but it has no
built-in set for it. DocGuard cannot tell a missing section from one written in
that language. So a required heading that has no English form, no marker and no
`docs.labelAliases` entry does not produce a missing-section finding (STR003 and
its siblings). `guard` lists the document under "DocGuard could not read". In
`guard --format json`, it appears in `strict.couldNotRead`. The entry gives the
cause `language-not-supported`, the language and the fix. That entry never
changes the exit code. Add a marker or an alias and the entry disappears.

## Documents named by language

With `docs.language` set, the name of a document can say that it is in another
language: `README.pt-BR.md`, `docs-canonical/ARCHITECTURE.pt-BR.md`, or a file
under `i18n/pt-BR/` or `locales/pt-BR/`. DocGuard resolves its labels with the
set for that language. It measures or skips its text metrics as for that
language. DocGuard never guesses the language from the text. Without
`docs.language`, it guesses nothing.

## What is skipped, and why

If a check cannot judge a document because of its language, it says so. It does
not pass silently and does not invent a number.

| Check | In a language other than English |
|---|---|
| Passive voice (DQ001), Flesch Reading Ease and Flesch-Kincaid (DQ004, DQ005) | Skipped, because the rules are English grammar. DocGuard reports the reason `language-not-supported`. It gives no number and no finding, and the score does not count it. |
| Negation (DQ007), conditional (DQ008), compound requirement (DQ003), ambiguous pronouns (DQ002) | Run for `pt` (`pt-BR`, `pt-PT`) and `es` (every `es-*`). They use the word lists that a native speaker reviewed on 2026-11-17 (see below), and the same thresholds as English. Skipped for every other language, with the reason `language-not-supported`. |
| Sentence length (DQ006) | Runs where the script separates words with spaces. Skipped for `zh`, `ja`, `th`, `lo`, `km`, `my`. |
| Docs-Diff's tech stack, Metrics-Consistency, semantic claims | Report `language-not-supported` for the documents they would have read. |
| Agent-instruction files (`AGENTS.md`, `CLAUDE.md`, ...) and the instruction audit | Out of scope. They get no alias and no `language-not-supported` entry. |

For a non-English `docs.language`, the tokenizer and the sentence splitter handle
Unicode (`não` is one word). For English, they are unchanged.

## What the writers do

- `docguard init` and `docguard generate` write the marker under each required
  heading of the documents they create, in English too. If `docs.language` is
  `pt` or `es`, the heading text is the first alias of the set. For any other
  language, the heading is English and the marker carries the id. A new
  `CHANGELOG.md` gets `## [Não lançado]` or `## [Sin publicar]` plus its marker,
  and `## [Unreleased]` otherwise.
- `docguard generate --plan --write` and `sync` put a generated block under the
  heading that already holds the section, in any accepted form. If no heading
  exists, they write the first alias plus the marker. They never write an English
  heading into a translated document. For a language with no set, they write the
  block without a heading and report it.
- `docguard fix --write` inserts the changelog section as `## [<first alias>]`
  plus the marker.
- No existing document is rewritten by `init` or `generate`.

## Word lists for the text metrics (`pt` and `es`)

Negation (DQ007), conditional (DQ008), ambiguous pronouns (DQ002) and
compound sentences (DQ003) count the words of a closed list for each language. A
native speaker reviewed the Portuguese and Spanish lists on 2026-11-17 (task T033
of spec 104). They live in one module, `cli/shared-prose-words.mjs`. DocGuard
matches a whole word and ignores case. Accents are optional in the text (`nao`
counts as `não`), but DocGuard never adds them: `é` is not the conjunction `e`,
`sí` ("yes") is not `si` ("if"), and `él` counts only with its accent because
`el` is the article. A hyphen between letters belongs to the word, so `e-mail`,
`não-funcional` and `configura-se` never match `e`, `não` or `se`. A phrase
matches across spaces. The thresholds are the English ones: pronouns over 15% of
the words, compound sentences over 35% of the sentences, negation over 20%,
conditionals over 30%. `<!-- docguard:quality
negation-load off — reason -->` works as in English.

| Metric | Portuguese (`pt`) | Spanish (`es`) |
|---|---|---|
| Negation | não, nunca, jamais, nenhum, nenhuma, nenhuns, nenhumas, nem, ninguém, nada, tampouco | no, nunca, jamás, ningún, ninguno, ninguna, ningunos, ningunas, ni, nadie, nada, tampoco |
| Conditional | se (see below), caso, quando, sempre que, a menos que, a não ser que, salvo se, exceto se, contanto que, desde que, somente se, apenas se, só se, até que, caso contrário, senão | si (without the accent), cuando, siempre que, a menos que, salvo que, excepto si, en caso de, en caso de que, con tal de que, solo si, sólo si, hasta que, de lo contrario, si no |
| Ambiguous pronouns | isso, isto, aquilo, ele, ela, eles, elas, este, esta, estes, estas, esse, essa, esses, essas, seu, sua, seus, suas, dele, dela, deles, delas | esto, eso, aquello, él (with the accent), ella, ellos, ellas, este, esta, estos, estas, ese, esa, esos, esas, su, sus |
| Non-atomic sentence | e também, e depois, e então, assim como, bem como, além de, além disso, adicionalmente, ademais, outrossim, or two or more "e" in one sentence | y también, y luego, y después, así como, además de, además, adicionalmente, asimismo, a su vez, or two or more "y" or "e" in one sentence |

Portuguese `se` is also the reflexive pronoun (`o arquivo se encontra`,
`configura-se`). In technical text, the reflexive is far more common than the
conditional. So `se` counts only as the first word of a sentence or right after a
comma, and never after a hyphen. This misses some conditionals in the middle of a
sentence, which is the safer side. DocGuard counts `desde que` as "provided
that". Its time sense ("since") is less common in requirement-style text.

Left out on purpose: `sem` and `sin` ("without"; English does not count it
either), `enquanto` and `mientras` (mostly temporal), the articles and clitics
`o a os as lhe` and `lo la los las le les`, `el` without the accent, and `sí`
with it. Portuguese often omits the subject pronoun, so its pronoun share is
lower than in English. The threshold stays the same. To correct a list, open an
issue or a pull request.

## Open

DocGuard skips passive voice and the two Flesch scores for every language except
English, because their rules are English grammar and syllables. Every other
language keeps sentence length only. A language other than `pt` and `es` has no
reviewed word lists, so DocGuard skips the four metrics above and does not guess.
The heading and word sets are data. To correct one, open an issue or a pull
request. The marker and `docs.labelAliases` work in the meantime.
